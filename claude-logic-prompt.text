### 1. executeWorkflowTransition

**#1 · L34–35, L41–43: guard evaluation and target selection**
- *Why sensitive:* This decides which target is chosen, so its result goes straight into `nextState`.
- *Fault:* Negate the guard (`!candidate.guard(...)`), or change `!candidate.guard` to `candidate.guard`.
- *Impact:* The wrong branch wins, so `nextState` differs, or a valid transition returns `BLOCKED`.

**#2 · L54: target-exists check**
- *Why sensitive:* It is the last gate before `TRANSITIONED`.
- *Fault:* Drop the negation or the whole check.
- *Impact:* Either every valid transition returns `FATAL`, or a transition to a nonexistent state returns `TRANSITIONED`.

**#3 · L38–40: guard exception handler**
- *Why sensitive:* It is the only place errors are turned into a status.
- *Fault:* Replace the `return` with `continue`.
- *Impact:* `GUARD_EXCEPTION` disappears and a later fallback transition fires silently.

**#4 · L49: `!resolvedTarget` → BLOCKED**
- *Why sensitive:* It separates "no guard passed" from success.
- *Fault:* Remove the check.
- *Impact:* `workflow.states[null]` fails, so `BLOCKED` becomes `FATAL` with the message "does not exist: null".
