### Prompt 1: Phase 1 — Strategic / Sensitive Bug Location Analysis

Use this prompt first to evaluate whether the LLM can identify fault-sensitive locations in a target function.

```text
You are an expert software testing and mutation analysis assistant.

I am analyzing the following backend method to identify its "strategic/sensitive bug locations"—defined as critical code locations, expressions, or branch decisions where the introduction of a fault/mutation is most likely to directly propagate and alter the program's observable output or state, rather than being masked or absorbed.

Here is the source code:
---
[PASTE METHOD / FUNCTION SOURCE CODE HERE]
---

Task Requirements:
1. Identify between 2 to 5 "Strategic / Sensitive Bug Locations" in this function.
2. For each identified location, provide:
   - Location: Exact line number(s) or statement.
   - Sensitivity Rationale: Why a bug introduced here directly alters program output/state rather than remaining silent or masked.
   - Fault Scenario: A concrete example of a likely fault/mutation at this spot (e.g., boundary condition swap, inverted check, dropped calculation, or null-mishandling).
   - Observable Impact: Exactly how the return value or failure state diverges from specification when this spot is faulted.
3. Rank the identified locations from Highest Sensitivity to Lowest Sensitivity.

```

Use this prompt to generate test suites that directly target the identified critical points to maximize mutation kill rate and coverage.

```text

Below is a backend method along with its identified "strategic/sensitive bug locations" (critical points where a fault directly alters output behavior).

Source Code:
---
[PASTE METHOD / FUNCTION SOURCE CODE HERE]
---

Sensitive Locations Identified:
---
[PASTE OUTPUT FROM PROMPT 1, OR LIST THE KEY CRITICAL LINES/CONDITIONS]
---

Task Requirements:
Generate a comprehensive, targeted test suite designed specifically to cover and trigger faults at these strategic locations:
1. For each test case, supply the following metadata:
   - Test ID (e.g., TEST-SEN-01)
   - Targeted Sensitive Location (Line / Condition)
   - Test Category (Normal, Boundary, Invalid Input, or Edge Case)
   - Exact Inputs
   - Expected Output / Behavior
   - Targeted Fault / Kill Objective (which subtle bug at this spot will this test catch?)
2. Provide executable test code compatible with Vitest / Jest (JavaScript/TypeScript).
3. Ensure assertions are strict and deterministic, avoiding non-asserted executions.

```
